# Айсберг — мониторинг почвы

Интерактивный прототип интерфейса анализа почвы. Один автономный HTML-файл: стили, графика и логика встроены. Серверная часть, установка зависимостей и сборка не нужны.

## Возможности

- Четыре металла: Pb, Cd, Cu и Hg.
- Параметры почвы, динамика, схема проб и история анализов.
- Два примера в настройках: показатели в пределах нормы и превышение по свинцу и кадмию.
- Симуляция нового анализа, CSV-экспорт и печать отчёта в PDF.
- Адаптация к мобильным экранам.

Измерения и пороги демонстрационные. Подключение к устройству симулируется. История сохраняется только в текущем браузере при доступности локального хранилища; между посетителями она не синхронизируется.

## Открыть локально

Откройте `index.html` в современном браузере. Интернет не требуется.

## Опубликовать через веб-интерфейс GitHub

1. Войдите в GitHub и откройте https://github.com/new.
2. Назовите репозиторий, например `iceberg-demo`. Для простого размещения на GitHub Free выберите **Public**: исходники и демо будут публичными. Не включайте автоматическое создание README — он уже подготовлен. Нажмите **Create repository**.
3. В пустом репозитории нажмите **uploading an existing file**. Если репозиторий уже содержит файлы, используйте **Add file → Upload files**.
4. Загрузите **содержимое** подготовленной папки: `index.html` и `README.md`. Не загружайте ZIP и не помещайте файлы во вложенную папку `github-pages`.
5. Внизу страницы укажите сообщение, например `Add Iceberg demo`, и нажмите **Commit changes**. При наличии выбора сохраните изменения в ветку `main`.
6. Проверьте, что `index.html` виден прямо на главной странице репозитория.
7. Откройте **Settings → Pages**. В разделе **Build and deployment** установите:
   - **Source:** `Deploy from a branch`;
   - **Branch:** `main` (или фактическая основная ветка, если она называется иначе);
   - **Folder:** `/ (root)`.
8. Нажмите **Save**. Подождите завершения публикации: ссылка появится в **Settings → Pages**. Состояние также можно посмотреть во вкладке **Actions**, в запуске `pages build and deployment`.
9. Откройте **Visit site**. Обычный адрес проекта: `https://ВАШ-ЛОГИН.github.io/iceberg-demo/`. Точный адрес берите из настроек Pages. Первичная публикация может занять до 10 минут.

Свой workflow, npm, Git CLI и домен не требуются. GitHub сам выполняет публикацию из выбранной ветки.

## Проверка после публикации

- Откройте настройки (шестерёнка) и выберите «Есть превышение нормы».
- Убедитесь, что главная карточка стала предупреждающей, а Pb и Cd выделены.
- Переключитесь на пример «Всё в пределах нормы».
- Проверьте страницу на телефоне.

## Обновление демо

Через **Add file → Upload files** загрузите новую версию `index.html` в тот же корень репозитория и нажмите **Commit changes**. GitHub Pages обновит сайт автоматически после завершения публикации. Адрес останется прежним.

## Если сайт не открывается

- Проверьте, что файл называется точно `index.html`, строчными буквами, и расположен в корне выбранной ветки.
- Убедитесь, что в Pages выбраны нужная ветка и `/ (root)`.
- Проверьте завершение публикации во вкладке **Actions**.
- При старой версии страницы обновите её без кеша или откройте в приватном окне.
